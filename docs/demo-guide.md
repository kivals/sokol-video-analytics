# Инструкция: как превратить прототип СОКОЛ в «живое» демо

## Часть 1. Загрузка своих видео

### Требования к роликам

| Параметр | Требование | Почему |
|---|---|---|
| Количество | ровно 6 файлов | сетка мониторинга рассчитана на 6 «камер» |
| Имена | `camera-1.mp4` … `camera-6.mp4` | сценарии привязаны к именам |
| Формат | mp4, кодек H.264 | гарантированно играет во всех браузерах |
| Длительность | 2–4 минуты | цикл незаметен, разметка не разрастается |
| Съёмка | **строго статичная камера** | рабочая зона рисуется один раз; дрожание выдаст фейк |
| Содержание | 5–8 смен деятельности, на 1–2 видео — «нарушения» (телефон, уход из зоны) | на этом строится сценарий показа |

Если ролики в другом формате — перекодируйте:

```bash
ffmpeg -i исходник.mov -c:v libx264 -pix_fmt yuv420p -an app/public/videos/camera-1.mp4
```

### Куда класть

Просто в `app/public/videos/` — файлы подхватываются без перезапуска
(в git они не попадают, это настроено).

### Подписи камер

Названия и цеха меняются в `app/src/data/cameras.json`:

```json
{ "id": "camera-1", "name": "Камера 1 — Токарный участок", "area": "Цех №1", "video": "/videos/camera-1.mp4" }
```

Поменяйте `name` и `area` под ваши видео («Камера 1 — Сварочный пост», «Цех №3» и т.д.).

## Часть 2. Разметка (самое важное)

Запустите dev-сервер: `cd app && npm run dev` → http://localhost:3000

### Шаг 1. Классы действий

Сначала решите, какие классы вам нужны. Правятся в `app/src/data/classes.json`:

```json
{ "id": "work", "name": "Работа за станком", "color": "#22c55e", "severity": "normal" }
```

- `severity: "normal"` — обычная работа (зелёная плашка);
- `"warning"` — жёлтое предупреждение (ожидание, отсутствие);
- `"violation"` — красное нарушение (телефон и т.п.) — автоматически попадёт
  в счётчики нарушений, ленту событий и аналитику.

Важно: страница «Настройки» тоже позволяет редактировать классы, но это
витрина для показа — реальные классы для мониторинга и аналитики берутся
из этого JSON. Меняйте файл.

### Шаг 2. Зона и сегменты в редакторе

Откройте **Разметка** (`/annotation`), выберите камеру в выпадающем списке
справа сверху.

**Рабочая зона:**
- зажмите мышь на пустом месте видео и растяните прямоугольник — появится
  пунктирный превью, отпустите — зона зафиксируется;
- существующую зону можно перетаскивать мышью;
- «Сбросить зону» вернёт рамку почти на весь кадр.

**Сегменты действий:**
1. Проиграйте видео до момента смены деятельности.
2. Нажмите «Добавить сегмент с текущего момента» — создастся сегмент от
   текущей секунды на 10 секунд вперёд.
3. В таблице поправьте: конец сегмента (в секундах), класс (выпадающий
   список), уверенность (0.94–0.99 выглядит правдоподобно, к ней в рантайме
   добавится дрожание ±1%).
4. Повторите на каждую смену действия. **Разметьте всю длину видео** — от 0
   до последней секунды, без дыр: плашка и таймлайн зациклены по длине
   разметки, недоразмеченный хвост будет «глючить».

При сохранении сегменты автоматически сортируются по времени. Если введёте
мусор в число — поле откатится, выход за диапазон — обрежется.

### Шаг 3. Сохранение и проверка

- **«Сохранить»** — разметка сохраняется в браузере (localStorage) и
  мгновенно применяется везде: откройте Мониторинг или карточку камеры и
  убедитесь, что плашки переключаются в нужные моменты.
- **«Сбросить к исходной»** — откат к файлу из проекта, если напортачили.

### Шаг 4. Точечные нарушения (тосты)

Всплывающие уведомления («Отсутствует защитная каска») — это отдельные
события, не привязанные к классам. Они добавляются руками в JSON разметки,
массив `events`:

```json
"events": [
  { "time": 63.5, "type": "violation", "title": "Отсутствует защитная каска" },
  { "time": 118.0, "type": "warning", "title": "Превышено время простоя станка" }
]
```

`time` — секунда видео. Тост всплывёт на экране мониторинга, когда видео
дойдёт до этой секунды (один раз за цикл), событие попадёт в ленту камеры и
в аналитику. Не переборщите: 1–2 на видео достаточно.

### Шаг 5. Зафиксировать разметку в проекте

Пока разметка живёт в localStorage — она только в вашем браузере. Чтобы она
стала «заводской» (работала на любом компьютере и после чистки браузера):

1. В редакторе нажмите **«Экспорт JSON»** — скачается файл.
2. Если добавляли `events` — впишите их в скачанный файл (экспорт сохраняет
   уже существующие).
3. Положите файл в `app/src/data/scenarios/camera-N.json` (замените старый).
4. Повторите для всех 6 камер.

Проверка полного цикла: «Сбросить к исходной» в редакторе — разметка должна
остаться вашей (теперь она и есть исходная).

## Часть 3. Что умеет каждая страница

### Мониторинг (`/`) — главный экран показа
- Сетка 6 камер: зацикленное видео, голубая рамка рабочей зоны, плашка
  текущего действия с процентом уверенности (дрожит, «как у живой модели»),
  индикатор LIVE.
- Плашка меняется с задержкой 0.5–1.5 с после реальной смены — имитация
  «времени реакции системы» (по ТЗ ≤ 2 с).
- Статусная строка каждой плитки: `LIVE • 25 fps • задержка X.X с` — цифры
  обновляются раз в 2 секунды реальными запросами к API (видно в
  DevTools → Network, если гости захотят посмотреть).
- Меню **⋮** на плитке → «Симулировать обрыв» — плитка показывает помехи и
  «НЕТ СИГНАЛА», повторный клик восстанавливает. Эффектный момент для
  демонстрации отказоустойчивости.
- Тосты нарушений всплывают справа внизу по таймкодам из `events`.
- Клик по плитке → карточка камеры.

### Камера (`/camera/[id]`)
- Крупный плеер с зоной и плашкой.
- Цветной таймлайн разметки под видео — **кликабельный**, перематывает видео
  (удобно на показе: «а вот здесь система зафиксировала нарушение — смотрим»).
- Лента событий справа: смены действий и нарушения с «настоящими» временами
  смены (отсчёт от 08:00).
- «Выгрузить разметку (JSON)» — скачивает актуальную разметку (включая ваши
  правки).
- «Открыть в редакторе» — прыжок в разметку этой камеры.

### Разметка (`/annotation`)
- Полноценный редактор (описан в части 2). На показе можно
  продемонстрировать как «инструмент ручной разметки для обучения моделей»
  из ТЗ — он реально работает.

### Модели (`/models`) — экран «для data science»
- Три модели: детектор работника, детектор положения рук, классификатор
  действий — версии, точность, задержка, F1, история обучений.
- **«Запустить обучение»** — главный вау-момент: ~90 секунд живого прогресса
  (эпоха 1→24, ETA, графики loss ↓ и accuracy ↑ рисуются на глазах).
  Остальные кнопки блокируются.
- Можно уйти на другую страницу или перезагрузить — обучение продолжается
  (job «на сервере»).
- По завершении: «Обучение завершено», версия модели +1, точность подрастает,
  в истории появляется новая строка. Запускайте обучение за ~2 минуты до
  того, как понадобится результат.

### Аналитика (`/analytics`) — экран «для руководителя»
- Карточки: точность классификации 97.4%, время отклика 1.2 с, потоков 6/6,
  счётчик обработанных кадров (тикает), нарушений за смену.
- Донат «Распределение времени по действиям» — считается из вашей разметки:
  сколько % смены работник реально работал.
- «Нарушения по камерам», график «Активность за смену» (08:00–16:00),
  таблица последних событий.
- Всё пересчитывается из сценариев: поменяли разметку — аналитика
  согласованно изменилась.

### Настройки (`/settings`)
- Классы действий (добавление/правка/удаление — сохраняется в браузере,
  витрина конфигурируемости).
- Параметры моделей: порог уверенности, окно кадров, интервал реакции —
  «Применить» показывает тост.
- Источники видеопотоков: таблица камер с RTSP-адресами — выглядит как
  реальная интеграция с камерами.

### Шапка (везде)
- Хлебная крошка, нагрузка GPU (гуляет 62–78%), счётчик кадров, «Система
  активна», текущее время — постоянная «жизнь» в кадре.

## Часть 4. Чек-лист перед показом

1. Видео на месте: 6 файлов в `app/public/videos/`, играют.
2. Разметка зафиксирована в `src/data/scenarios/` (не только в localStorage).
3. Показ вести на прод-сборке — быстрее и без dev-пауз:
   ```bash
   cd app && npm run build && npm start   # http://localhost:3000
   ```
4. Прогнать глазами: плитки играют и плашки переключаются → тост всплывает →
   карточка камеры → перемотка по таймлайну → запуск обучения → аналитика.
5. Браузер — Chrome, вкладка на весь экран, ноутбук не в режиме
   энергосбережения (троттлинг фоновых вкладок останавливает видео — держите
   демо активной вкладкой).
